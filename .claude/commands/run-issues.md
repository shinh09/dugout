상위 이슈 #$ARGUMENTS (비어 있으면 #1)의 남은 작업을 이어서 처리해 줘. 한 번 실행에 **최대 3개 이슈**까지만 해.

## 0. 먼저 할 일
- 내가 올린 열린 PR 중 Gemini 리뷰 댓글에 답하지 않은 게 있으면 그것부터 처리해 (댓글마다 반영 커밋 또는 미반영 이유로 답글, 마지막에 요약 댓글 1개)

## 1. 작업 고르기
- `gh api repos/{owner}/{repo}/issues/<상위번호>/sub_issues`로 열린 하위 이슈를 가져와
- 이미 열린 PR이 있는 이슈는 건너뛰어
- 순서: 앞선 작업에 의존하는 이슈는 뒤로 (예: 프로젝트 초기화 → 로컬 DB → CI → 인증 → 방송 CRUD → 송출·시청)
- 다음 이슈가 아직 머지되지 않은 PR의 코드에 의존하면, 그 PR 브랜치 위에 쌓지 말고 멈추고 보고해

## 2. 이슈 하나 처리
1. `/start-task <번호>`
2. `/plan <번호>` — 아래 멈춤 조건에 걸리지 않으면 승인을 기다리지 말고 진행
3. 기능 이슈면 qa 에이전트가 실패 테스트를 먼저 쓰고, 담당 에이전트가 구현
4. 테스트 통과 확인 → `/security-review` → `/ship`
5. PR을 올리면 머지를 기다리지 않고 다음 이슈로

## 3. 멈추고 나에게 물어볼 때
- 계획상 변경 파일이 5개 이상
- 새 의존성 추가, 파일·DB 삭제
- 설계 문서(`docs/design`)와 다르게 해야 하거나 정책에 없는 판단이 필요할 때
- 같은 테스트가 3번 연속 실패
- 외부 계정·API 키·Secrets가 필요할 때
- 실기기(PC 화면 공유, 휴대폰 카메라) 확인이 필요할 때

## 4. 끝나면 보고
- 처리한 이슈와 PR 링크 (머지 추천 순서 포함)
- 멈췄다면 이유와 내가 할 일
- 상위 이슈 진행률 (완료 / 전체)
